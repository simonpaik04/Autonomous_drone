# 선형모델 기초와 DNN 비행 제어 추론 학습 기록

날짜: 2026-07-31

## 1. Day 04에서 Day 05로 이어지는 흐름

Day 04의 목표는 지도학습에 사용할 입력과 정답을 만드는 것이었다.

```text
MPU6050 6축 원시값
→ PID 제어기
→ Roll·Pitch·Yaw 보정값
→ 입력 6개와 정답 3개 저장
```

Day 05의 목표는 저장한 관계를 학습한 신경망을 ESP32에서 실행하는 것이다.

```text
MPU6050 6축 값
→ 입력 정규화
→ 학습된 DNN 순전파
→ Roll·Pitch·Yaw 보정값 예측
→ 4개 모터 믹싱과 PWM 출력
```

즉, Day 04의 PID는 데이터를 만드는 선생님 역할을 하고 Day 05의 DNN은 그 입력·출력 관계를 근사한다.

## 2. 선형모델 순전파

가장 작은 모델은 입력 하나와 가중치 하나, 편향 하나로 표현한다.

```text
y = xw + b
```

- `x`: 입력
- `w`: 입력의 영향력을 조절하는 가중치
- `b`: 입력이 0일 때도 더해지는 편향
- `y`: 모델의 예측
- `yT`: 목표값

예측과 목표의 차이는 제곱오차로 계산한다.

```text
E = (y - yT)² / 2
```

`1/2`을 곱하면 미분할 때 제곱의 `2`와 약분되어 기울기 식이 간단해진다.

## 3. 경사하강법

예측 오차를 `yE = y - yT`라고 하면 각 변수의 기울기는 다음과 같다.

```text
dE/dw = yE × x
dE/db = yE
```

학습률 `lr`만큼 기울기의 반대 방향으로 값을 갱신한다.

```text
w = w - lr × dE/dw
b = b - lr × dE/db
```

반복 학습할수록 `y`가 `yT`에 가까워진다. 입력이 두 개라면 순전파와 각 가중치의 기울기가 다음처럼 확장된다.

```text
y = x1w1 + x2w2 + b
dE/dw1 = yE × x1
dE/dw2 = yE × x2
```

## 4. DNN 구조

드론 DNN은 입력층 6개, 은닉층 16개 두 개, 출력층 3개로 구성된다.

| 단계 | 계산 | 출력 크기 |
| --- | --- | ---: |
| 입력 | `X` | `1 × 6` |
| 은닉층 1 | `H = ReLU(X × WH + BH)` | `1 × 16` |
| 은닉층 2 | `M = ReLU(H × WM + BM)` | `1 × 16` |
| 출력 | `Y = M × WY + BY` | `1 × 3` |

ReLU는 음수를 0으로 만들고 양수는 그대로 통과시킨다.

```text
ReLU(x) = max(0, x)
```

### 파라미터 수

| 배열 | 크기 | 개수 |
| --- | --- | ---: |
| `WH` | `6 × 16` | 96 |
| `BH` | `1 × 16` | 16 |
| `WM` | `16 × 16` | 256 |
| `BM` | `1 × 16` | 16 |
| `WY` | `16 × 3` | 48 |
| `BY` | `1 × 3` | 3 |
| 합계 |  | **435** |

`model_data.cpp`에는 학습이 끝난 435개 가중치·편향이 C++ 배열로 저장되어 있다.

## 5. ArduinoEigen과 `Map`

`model_data.cpp`의 값은 일반 `double` 배열이다. ArduinoEigen의 `Map`을 사용하면 값을 복사하지 않고 배열을 행렬처럼 해석할 수 있다.

```cpp
WH = Map<Matrix<double, NUM_X, NUM_H, RowMajor>>(_WH);
BH = Map<MatrixXd>(_BH, 1, NUM_H);
```

가중치는 Python에서 내보낸 행 우선 순서를 유지해야 하므로 `WH`, `WM`, `WY`에는 `RowMajor`를 사용한다. 순서가 다르면 배열의 값은 같아도 다른 신경망이 된다.

## 6. 입력과 출력

### 입력 6개

```cpp
double x[6] = {AcXD, AcYD, AcZD, GyXD, GyYD, GyZD};
```

MPU6050의 signed 16-bit 값을 `32768.0`으로 나눠 약 `-1.0~1.0` 범위로 정규화한다.

### 출력 3개

```cpp
double BalX = y[0];
double BalY = y[1];
double BalZ = y[2];
```

예측된 세 값은 기존 PID의 Roll·Pitch·Yaw 보정값 자리에 들어간다. 이후 모터 믹싱 공식은 Day 03·04와 같다.

## 7. 오프라인 학습과 ESP32 추론

현재 ESP32 코드는 기체 위에서 모델을 학습하지 않는다.

1. Day 04 코드로 센서 입력과 PID 정답을 수집한다.
2. PC에서 데이터를 정리하고 DNN을 학습한다.
3. 학습된 가중치와 편향을 C++ 배열로 변환한다.
4. 배열을 `model_data.cpp`에 넣는다.
5. ESP32에서는 `dnn_predict()` 순전파만 실행한다.

이 구분이 중요한 이유는 학습에는 역전파와 많은 반복 계산이 필요하지만, 추론은 한 번의 순전파만 필요하기 때문이다.

## 9. Day 04 코드에서 이어받은 수정

- 드론 하드웨어와 DNN을 먼저 초기화한 뒤 자동 비행 태스크를 생성한다.
- LEDC 채널을 `ledcSetup()`한 뒤 모터 핀을 연결한다.
- 태스크 생성 결과를 확인하고 실패하면 모터를 시작하지 않는다.
- GPIO 0은 `INPUT_PULLUP`으로 설정해 입력이 떠서 의도치 않게 시작되는 것을 줄인다.
- 버튼 대기 루프에 `vTaskDelay()`를 넣어 코어를 계속 점유하지 않도록 한다.
- 현재 태스크 종료에는 `vTaskDelete(NULL)`을 사용한다.

## 10. Day 04와 데이터 스케일 비교

Day 04 예제는 센서 원시 정수값을 저장했지만 Day 05 추론 코드는 값을 `32768.0`으로 나눈다. 모델 학습 때도 반드시 같은 정규화를 적용해야 한다.

```text
학습 입력 전처리 ≠ ESP32 입력 전처리
→ 모델 출력이 의미 없는 값이 될 수 있음
```

학습 데이터 생성부터 배포까지 입력 순서와 단위, 정규화 공식을 하나의 규칙으로 유지해야 한다.

## 11. 시험 전 확인

- 처음에는 프로펠러를 분리한다.
- GPIO 0 버튼을 누르지 않았을 때 모터가 시작되지 않는지 확인한다.
- `throttle == 0`일 때 DNN 보정값과 네 모터 출력이 모두 0인지 확인한다.
- 센서 입력 6개의 순서와 학습 데이터 열 순서가 같은지 확인한다.
- DNN 출력 `BalX/Y/Z`의 최솟값·최댓값을 기록해 학습 범위를 벗어나지 않는지 확인한다.
- NaN이나 비정상적으로 큰 출력이 나오면 모터를 즉시 0으로 만드는 안전장치를 추가한다.
- DNN 제어와 기존 PID 제어를 같은 조건에서 비교한 뒤 실제 비행을 진행한다.
